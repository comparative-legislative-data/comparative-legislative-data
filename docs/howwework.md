# Ways of Working: Operator & Agent Guardrails

This document defines the strict operational rules and guardrails that **MUST** be read, verified, and complied with before undertaking any tasks in this repository.

---

## 1. Absolute Integrity & Non-Speculation

*   **We Never Guess — We Always Check:**
    *   Do not guess, assume, or infer specifications of the VPS, host provider, memory usage, disk storage, file size, or directory path.
    *   If system specs or status are needed, execute an approved diagnostic check (e.g., `df -h`, `free -m`, `uname -a`) or read the verified specs in `docs/ops.md`.
    *   If diagnostic commands are unavailable, denied, or fail, immediately halt and report the block to the user.
*   **No Fictional Outputs:**
    *   Never report mock sizes, durations, or statuses as actual results. All metrics reported must be parsed directly from active terminal logs or files.

---

## 2. Strict Workspace Boundary Containment

*   **Boundary Restriction:**
    *   The agent is strictly confined to the directory `/home/steven/Documents/github/comparativelegislativedata`.
    *   Do not view files, list directories, run commands, or execute grep searches on any adjacent directories (e.g., `hetznercoolifymaster`) under any circumstances.
    *   Do not attempt to read system settings, configuration directories, or credentials outside the repository scope.

---

## 3. Blocker & Interruption Protocols

*   **Command Rejections / Stops:**
    *   If the user denies a proposed command or types "stop", immediately cease all tool actions, background tasks, and diagnostic attempts. Await explicit user instruction.
*   **Blocker Protocol:**
    *   If a task encounters a permission gate, directory wall, or network failure, do not attempt to bypass it using alternate paths or guessing credentials. Stop and request the correct parameter or permission directly.

---

## 4. Mandatory Verification Norms

*   **File Integrity Check:**
    *   Every compressed file (ZIP, GZ), database (SQLite), or CSV generated by the pipeline must be tested locally for integrity and syntax validity using diagnostic commands (e.g., `zip -T`, `gzip -t`, `python3 -m py_compile`) before reporting completion.
*   **Deployment Gate:**
    *   Never deploy modified SvelteKit or backend endpoints without verifying that compile builds succeed and system services restart cleanly.
